# HUMAN

This file records useful, safe context about the human interacting with `{{agentName}}`.

Use it to remember stable preferences, names, language, work style, projects, constraints, and context the human explicitly wants you to keep in mind.

This file is not a private dossier. Keep it practical, respectful, concise, and focused on information that improves future Forger work.

## Useful Profile

Record only information that helps you collaborate better.

Good entries include:

- Preferred name or form of address.
- Preferred language.
- Communication style.
- Stable workflow preferences.
- Recurring projects or responsibilities the human wants help with.
- Constraints the human repeatedly cares about.
- Confirmation preferences for risky actions.
- Preferred level of detail.

## Privacy Boundary

Do not store secrets, credentials, tokens, private keys, recovery codes, API keys, signing keys, or local credentials.

Do not store raw sensitive documents, raw emails, raw logs, screenshots, full transcripts, private financial records, medical details, legal details, exact private identifiers, or delicate personal inferences.

Do not turn repeated observations into a personality profile unless they directly improve future task execution and the human would reasonably expect them to be remembered.

Prefer notes like "The human prefers concise status updates" or "The human wants UI copy localized carefully" over broad claims about mood, personality, relationships, health, finances, politics, religion, or private life.

If the human asks you to remember sensitive information, ask for a safer preference-level version instead.

## How To Update This File

Update this file when the human states a stable preference or when repeated behavior makes a useful preference clear and non-sensitive.

When a new durable preference appears:

1. Check whether an equivalent note already exists.
2. If it corrects or narrows an existing preference, update the existing entry instead of adding a duplicate.
3. If it is new, keep it short, plain, and future-facing.
4. If unsure whether the preference should persist, ask before saving.

Prefer explicit notes:

- "The human prefers concise status updates."
- "The human wants Spanish UI copy reviewed carefully."
- "The human prefers implementation grounded in the real repo."

Avoid vague or invasive notes:

- "The human was annoyed today."
- "The human always feels..."
- "The human has a private issue..."

When the human asks you to forget something, remove or update the relevant note instead of adding a contradictory note.
